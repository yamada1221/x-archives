# 拡張機能からの自動アーカイブ（v1.3.11）

更新：2026-11-14。対象はPC版Chrome／Edge、Manifest V3。返信タブに含まれるプロフィール本文も、同じアカウントと照合できればプロフィール確認として扱う。

## 使い始める

1. `downloads/x-tracker-mute-capture-v1.3.11.zip` を展開し、拡張機能の管理画面から読み込む。更新する場合は現在の展開先へ全ファイルを上書きして「再読み込み」を押す。v1.3.8〜v1.3.10で接続済みなら追加の接続テストは不要。
2. 拡張機能の「自動アーカイブの設定・実行状況」を開く。
3. owner・repo・データファイル・Fine-grained PAT（Contentsの読み書き）を保存し、必要なホストへのアクセスを許可する。
4. 「接続テスト（1件）」を実行する。公開プロフィール @X を実際に保存し、保存された本文を照合する。テストの途中経過は画面を閉じても保持する。
5. 本文確認に合格したら「自動保存を開始」。通常の追加はトラッカーで記録対象を選択し、GitHubに保存する。

## 実行と保存先

- 既定はarchive.li（archive.today系）。同一オリジンの通常保存フォーム `/submit` または `/submit/` に対象を入力し、フォームのGET／POSTを変更せずに送信し、サービスの隠し項目も保持する。検索フォームへは送信しない。`/wip/…` は受付情報として保存し、完成URLへ進んだ後に保存本文を照合する。既存の保存URLに案内された場合も本文を確認する。
- 設定画面でGhostarchiveも選択できる。Ghostarchiveの通常フォームを、拡張機能が作ったバックグラウンドタブで操作する。実測した送信先は `/archive2`、POSTパラメータは `archive`。
- 結果の `/archive/ID` を受付情報として保存する。処理中・結果URL発行・HTTP成功だけでは完了にしない。
- archive.liでは保存結果の長い共有URLから対象URL・UTCの取得時刻を取り出し、保存本文のプロフィール領域を照合する。メタデータのみ、処理中URL、ログイン画面、別アカウント本文では完了にしない。
- Ghostarchiveでは保存結果のNoscript表示と、その結果に対応する同一Ghostarchive内の保存本文フレームだけを調べる。対象URL、取得時刻、プロフィール本文、ハンドル、フォロー先リンク、取得できればプロフィール操作領域の数値IDを照合する。
- 数値IDを保存本文から確認できないときは、送信前後の同じIDの照会とプロフィールの表示名・自己紹介の一致も必要とする。空の自己紹介を理由に即成功・即失敗にしない。
- プロフィール本文と、画面に保存された投稿本文の確認結果を分ける。全投稿や画像・動画全体の保存は保証しない。
- 人間確認・構造変更・アクセス制限では手動確認へ移す。CAPTCHAを自動で処理しない。

通常フォームでのサービス実測では、2026-10-26に公開プロフィール @X の新規保存と、プロフィール・投稿本文の表示を確認した：
https://ghostarchive.org/archive/l8oxw

これはサービスの保存確認であり、各利用者の拡張機能・ネットワークでの接続テストに代わるものではない。

## 更新時の扱い

v1.2.0の保存先未指定設定はarchive.liを既定とする。旧版のGhostarchive接続テストをarchive.liへ流用せず、保存先のアクセス許可と接続テストを改めて必要とする。設定画面で接続先を保存する際、同じリポジトリならPATは再入力不要。保存済み・送信済みのGhostarchiveジョブは保持し、元の保存先で照合・同期を続ける。未送信ジョブは新しい保存先での走査へ引き継ぐ。

## v1.3.11のプロフィール確認範囲

プロフィールの依頼は、同じアカウントのプロフィールまたは返信タブの保存を候補にできる。既存の本文・数値ID・日時の照合に通ることを条件とし、実際に保存されたURLと依頼元のURLを区別して履歴へ記録する。返信タブの選択状態も確認できた場合は、プロフィールと返信タブの両方を確認済みとする。返信タブの本文が確認できなければプロフィール確認だけを記録する。

返信タブの依頼は引き続き返信タブの本文確認を必要とする。プロフィールだけの保存から返信タブの確認を推測しない。既存のプロフィール保存や同じ結果URLの確認済み範囲は保持する。以前のURL不一致または返信タブの取り違え表示で止まったプロフィール依頼は、実行担当のブラウザが同じ結果を一度だけ再確認し、再送しない。

## v1.3.10の保存対象の照合

設定画面は各依頼の「プロフィール」「返信タブ」と保存対象URLを表示する。開いている個別の保存結果は読み取りだけで対象URLを確認し、必要な内容を確認できるものを候補にする。プロフィールの依頼には返信タブの保存も含む。対象URLが分からないページや別のアカウントは候補にしない。保存一覧由来のリンクは本文未確認として扱い、最終的な対象URL・日時・本文・数値IDの照合を維持する。

URL情報不足、別アカウント、返信タブの依頼にプロフィールしかない場合を区別して案内する。保存対象の不一致で手動確認となった依頼に限り、明示的な手動操作で別の個別結果URLへ差し替えられる。以前のURLは履歴へ保持し、種別や送信回数を変えず、新しいURLにも従来の全文照合を行う。

## v1.3.9で統合した更新

- archive.liのGET保存フォーム、フォーム診断、開いている保存結果の候補選択、結果URLの入力保持。
- 実際の保存HTMLに合わせたプロフィール本文認識と、既知の読み取りエラーに対する一度だけの再照合。利用者のHTMLやジョブ台帳は公開ソースへ含めない。
- 人間確認・アクセス制限・送信済み結果不明の待機理由を表示し、新規依頼を止めて既存結果を再確認する。人間確認自体は利用者が行う。更新や再起動でタブの対応が失われた場合は対象URL・保存時刻を照合して拾い直す。
- 「記録対象」の独立した「クソリプ」タグは、プロフィールと返信タブを別々の依頼・保存履歴として扱う。プロフィールが保存済みでも返信タブを対象にし、返信タブの選択状態と同一アカウントを本文で確認する。全返信の収集や保存先での取得成功は保証しない。
- 設定画面には直近100件と、それ以前の確認が必要な全依頼を返し、確認待ち件数と依頼を先頭へ表示する。人間確認やアクセス制限も含む。トラッカー向けの返却は直近100件を維持する。

## 対象と周期

「記録対象」の公開Xプロフィールの初回保存と、「クソリプ」タグがある記録対象の返信タブ保存。各種別の既存の保存済み・監視のみ・個別停止は除外する。初回走査・トラッカーのGitHub保存完了通知・6時間ごとのalarmで候補を回収する。1走査で最大5件、送信は1件ずつ、間隔60秒以上、直近24時間に最大20回、処理中は最大5件。

処理中の確認は1分ごとのalarmを目安に進める。時刻をまたいでService Workerが停止しても、永続化した状態から再開する。ブラウザ終了・スリープの未実行分を回数分まとめて送信しない。初期の有効化は接続テストの合格後であり、インストールだけでは送信しない。

## 進捗・同期・競合

端末内の接続先設定はchrome.storage.local、認証情報・ジョブ・受付情報・未同期結果・実行ロックは拡張機能オリジンのIndexedDBへ保存する。storage.localにはトークンを含めず、StorageArea.setAccessLevelがないブラウザでもcontent scriptから認証情報を読めない構成とする。

共有設定は `data/auto_archive_config.json`、共有ジョブ台帳は `data/archive_jobs.json`。拡張機能からGitHub Contents APIのSHA付き更新で保存する。実行担当はリポジトリごとに1ブラウザプロファイルを登録する。

保存依頼前に共有台帳へ送信開始と回数を予約する。登録・数値ID・個別停止・実行担当を再確認してからPOSTする。受付後は端末内への保存を優先し、GitHub同期だけが失敗した場合は結果を保持して同期を再試行する。

POST後に実行が停止して受付URLが不明な場合、保存先の結果画面・検索で照合する。タイムアウトやリース切れだけで依頼を再送しない。「この結果の本文を再確認」は、指定URLの本文を検証する操作であり、無条件に保存済みへ変更する操作ではない。

既存の `archives` へ結果を追加し、メモ、Threads、ミュート確認、監視状態、過去の保存URLを保持する。同期中の登録削除・別人への変更では登録を復活させない。旧保存済みは履歴を残し、新しい本文検証に合格した記録とは区別する。

新規の手動結果もURL形式だけでは保存済みにしない。保存ヘルパーの本文確認チェックで手動確認を記録できる。魚拓の既存GitHub Actions検証は維持する。

## 検証

- `node --test tests/test_auto_archive.cjs tests/test_receipt_picker.cjs tests/test_receipt_recovery.cjs tests/test_review_backlog.cjs`：状態遷移、二重送信、通信断、同期待ち、対象削除、ID・URL検証、権限境界、保存枠、接続テスト、返信タブ、結果候補選択、再読み込み時の追跡、100件を超える一覧と公開状態の制限。
- Playwright導入後の `node --test tests/test_archive_today_forms.cjs tests/test_auto_options.cjs`：GET／POSTフォーム、合成した保存本文、返信タブ、確認待ち優先表示、URL入力保持。外部通信をモックする。
- `test_saved_archive.cjs` と `test_additional_archives.cjs` はローカルの実HTMLが環境変数で指定された場合だけ追加検証する。後者は `SAVED_ARCHIVE_JOBS` にローカルの対応ジョブJSONも指定する。公開CIでは個人のHTMLやジョブ情報を必要としない。
- `node tests/browser_auto_archive.cjs` と `ARCHIVE_PROVIDER=ghostarchive node tests/browser_auto_archive.cjs`：本物のMV3拡張をインストールし、設定UI、IndexedDB、alarm、保存先フォームPOST、保存本文フレーム、Service Worker停止・再開とGitHub同期を検証。外部サービスの応答は固定フィクスチャを使用する。archive.liでは通常フォームの隠し項目の保持、WIPから完成URLへの遷移、保存本文を検証し、Ghostarchiveでは保存本文フレームを検証する。通信を置き換える前にネイティブのWorkerGlobalScope.fetchも検証する。
- ブラウザ検証では、利用者による許可後を再現するため、一時コピーのmanifestに検証用のホスト権限を事前付与する。配布ZIPのmanifestは任意権限のまま。
- 既存のミュート取り込み、プロフィール取得、トラッカー同期の回帰テストも実行する。

### archive.liの実サイト確認の制限

2026-10-26の作業環境ではarchive.liへの接続ができず、実サービスでの新規保存・本文照合は未検証。通常フォームと保存ページの構造を前提としたアダプターであり、構造を確認できない画面では手動確認へ移す。利用者のブラウザで接続テストが本文確認まで通ることを自動送信の条件とする。

## 今回の範囲

通常プロフィールと対象アカウントの返信タブの初回保存、途中再開、本文検証、結果同期、手動確認への移行。変更時・30日ごとの再保存、個別投稿の保存、全返信の収集、別サービスへの自動切替は対象外。
