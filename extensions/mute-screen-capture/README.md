# Xトラッカー 自動アーカイブ・ミュート取り込み v1.3.11

PC版Chrome / Edge用のManifest V3拡張です。iPhoneのXアプリでは使えません。

## 自動アーカイブ

拡張機能の「自動アーカイブの設定・実行状況」から設定します。

1. GitHubのowner・repo・データファイル（標準は `data/artists.json`）と、Contentsの読み書き権限があるFine-grained PATを保存します。既定の保存先はarchive.liです。Ghostarchiveも選べます。追加する権限はGitHub API・FxTwitter・選択した保存先と、保存先ページを操作するscriptingです。archive.liは同系列ドメインへの移動にも対応します。
2. 初めて設定したブラウザを実行担当に登録します。別PCへ移す場合だけ「このブラウザへ実行担当を引き継ぐ」を選びます。
3. 「接続テスト（1件）」で公開プロフィール `@X` を保存します。保存URLの受付だけでは合格にならず、数値ID・プロフィール本文まで確認できたときに接続テスト済みになります。
4. 「自動保存を開始」を押します。以降は、トラッカーで「記録対象」を追加してGitHubへ保存すると、拡張機能が未保存プロフィールを自動保存します。追加の取りこぼしは6時間おきに走査します。

既存の保存済みアカウントと「監視のみ」は新規保存の対象外です。ミュート画像からの新規登録も「監視のみ」のままです。今回は通常プロフィールの初回保存が対象で、全投稿収集や定期的な再保存は含みません。

ポップアップやトラッカーのタブを閉じても処理します。ブラウザ終了・PC電源OFF・スリープ中は待機し、起動・復帰後に続きを確認します。保存先側で受付済みの処理は、サービス側で継続する場合があります。

保存処理は1件ずつ、送信間隔60秒以上、直近24時間に最大20回です。Service Workerの停止に備えて進捗・受付URL・GitHub未同期の結果をIndexedDBへ保存します。GitHubの共有ジョブ台帳で実行担当・送信枠を予約するため、GitHubに接続できない間は新規送信を待機します。

### 手動確認が必要な場合

「保存先で確認」で拡張機能が作成した保存先タブを表示できます。人間確認は利用者が行ってください。人間確認の画面では「人間確認待ち」と表示し、新規依頼を待機します。確認後は約5分ごとに既存の結果を読み直します。「確認後に再確認」でもすぐ確認できます。受付結果が不明な案件は自動で再送しません。

更新・再起動などで元のタブを特定できない場合は、その理由を表示します。保存先の一覧などから個別の結果を開き、「開いている保存ページから選ぶ」→「この結果の本文を再確認」で照合してください。保存一覧そのもののURLは保存結果にはできません。

「GitHub同期待ち」は、受付情報・保存結果を端末内で保持し、同期だけを再試行している状態です。「走査・同期を実行」で再試行できます。新規保存を停止しても受付済みの結果確認・同期は継続します。

GitHubトークンをWebページ・保存先・共有JSON・ログへ渡しません。拡張機能オリジンのIndexedDBへ保存し、content scriptからは参照できない構成です。storage.localには接続先などの設定だけを保存します。ブラウザ保存をOS資格情報保管庫と同じ暗号化保存とは扱いません。

実装・動作確認の詳細はリポジトリの `docs/auto-archive-extension.md` に記載します。

## v1.3.11のプロフィール確認

同じアカウントの返信タブの保存にプロフィール本文が含まれ、従来のアカウント・数値ID・本文・保存日時の照合に通れば、その結果でプロフィールも確認済みにします。返信タブの選択状態も本文から確認できた場合は、プロフィールと返信タブの両方を確認済みとして記録します。実際に保存された返信タブのURLも履歴に残します。

プロフィールの保存依頼では、同じアカウントの返信タブの結果も候補に含めます。返信タブの保存依頼には、返信タブの本文確認が必要です。通常のプロフィール保存だけで返信タブを確認済みにはしません。

以前「保存先の対象URLが一致しません」「保存先は返信タブです…」で止まったプロフィール依頼は、更新後に登録済みの結果URLを一度だけ再確認します。保存依頼の送信回数・元の日時は保持します。v1.3.10からは同じフォルダに上書きして拡張機能を再読み込みします。

## v1.3.10の保存結果の選択

依頼ごとに「プロフィール」「返信タブ」と保存対象URLを表示します。「開いている保存ページから選ぶ」では、個別の保存結果の対象URLを読み取り、必要な内容を確認できる候補を表示します。プロフィールの依頼には返信タブの結果も含みます。本文の確認が終わるまでは保存済みにしません。

返信タブ用にプロフィールの結果を指定した場合や、別アカウント・URL情報を読み取れない場合は理由を分けて案内します。返信タブの保存からプロフィールを確認する扱いは、上記v1.3.11のとおりです。

保存対象の取り違えで確認待ちになった依頼は、「プロフィールの保存一覧を開く」または「返信タブの保存一覧を開く」から対応する保存履歴を探し、正しい種別の個別の保存結果URLへ差し替えて再確認できます。以前のURLは履歴に残し、保存依頼は出し直しません。差し替え後も対象URL・本文・アカウントの照合が完了するまでは保存済みにしません。

v1.3.9からは全ファイルを同じフォルダへ上書きして再読み込みします。接続テストをやり直す必要はありません。

## v1.3.9の公開版統合と確認待ち一覧

PC側で更新していたv1.3.1〜v1.3.8の変更を公開ソースと配布ZIPへ統合しました。設定画面は、直近100件より古い手動確認・受付結果不明・人間確認・アクセス制限の依頼も保持し、確認が必要な件数と依頼を一覧の先頭へ表示します。入力中の結果URLや返信タブの保存履歴は保持します。

更新はv1.3.10のZIPを展開し、現在読み込んでいる拡張機能フォルダへ全ファイルを上書きしてから、拡張機能の管理画面で「再読み込み」を押します。同じ拡張機能として更新するため、いったん削除して再インストールする必要はありません。v1.3.8からの更新では接続設定・保存済み履歴・送信済みの依頼を引き継ぎ、追加の接続テストは不要です。

## v1.3.8の返信タブ保存

「記録対象」のメモに独立した語として「クソリプ」があるアカウントは、プロフィールに加え、そのアカウントの返信タブも別の保存依頼・保存履歴として扱います。すでにプロフィールが保存済みのアカウントも返信タブを対象にします。「監視のみ」と自動保存オフは従来どおり対象外です。タグを外したり対象設定を変更した場合、未送信の依頼は中止します。

返信タブは `https://x.com/<ユーザー名>/with_replies` を保存し、保存本文内で同じアカウントの返信タブが選択されていることを確認します。プロフィールとは別の結果として記録し、従来のプロフィールの保存結果を上書きしません。Xや保存先が返信タブを取得できない場合は手動確認となり、保存成功と表示しません。保存先の人間確認や受付結果不明による待機も引き続き適用します。

返信タブで表示される範囲の保存であり、すべての過去の返信を収集する機能ではありません。保存先の制限により、実際の返信タブ保存については利用環境での確認が必要です。

## v1.3.7の人間確認・受付結果追跡の修正

送信後の人間確認ページを「受付結果不明」で打ち切っていた分岐を修正しました。結果URLがある人間確認ページも、保存成功には扱いません。人間確認・アクセス制限の待機中、または送信済みで結果を特定できない間は、新規依頼を増やしません。人間確認後は既存依頼の読み取りを再開し、既存の対象URL・本文・数値ID・保存日時の条件で照合します。

更新前に受付結果不明で停止した、このブラウザの送信済みarchive.liジョブは一度だけ再確認します。保存依頼は再送しません。拡張機能の再読み込みでセッション内のタブ対応が失われた場合、送信対象が一致するGET受付タブ、または対象URL・保存時刻が一致する開いたままの新しい保存結果を読み取ります。複数候補、古い保存、別アカウント、確認できない時刻は自動選択しません。元のタブが閉じられている場合などは手動で個別の結果を選ぶ必要があります。

48時間以上前の依頼でも、更新時の再確認または手動での結果確認を開始した時点から結果を確認できます。元の送信日時・送信回数・予約履歴・アカウント照合条件は保持します。保存先の人間確認は自動操作しません。

## v1.3.6の照合修正

実保存HTMLで確認した、ユーザー名に続く「Commentary account」等のラベルと、自己紹介の前の「Show translation」操作を本文から分離します。翻訳ボタンが存在するときだけ、その操作ラベルを除き、投稿者が書いた同じ文言は保持します。本文内の数値ID・表示名・自己紹介を使う確認条件は維持します。

この修正前に本文の読み取りで停止した、結果URLがある実行担当のプロフィールジョブを、更新後に一度だけ再照合します。同じ対象の保存依頼は送り直しません。受付結果不明・結果URLなし・別アカウントの数値IDなど、別の理由で停止しているものは再照合へ移しません。新しい読み取り処理でも照合できなければ再び手動確認で停止し、同じ版で再試行を繰り返しません。

## v1.3.5の保存本文認識

実際のarchive.li保存HTMLで、Xの`data-testid`属性が除去されることを確認しました。保存本文のプロフィール領域にある表示名・非リンクのハンドル・同一アカウントのFollowing/Followersリンクから認識します。プロフィールのヘッダー画像に紐づく`pbs.twimg.com/profile_banners/<数値ID>/...`も照合に使います。アバター画像IDや投稿中の画像からユーザーIDを推測しません。

既存の数値ID・対象アカウント・保存日時の確認条件は維持します。古い保存を採用する場合は、保存本文内の数値IDが必要です。更新後は登録済みの結果URLが入力欄に自動で入り、「この結果の本文を再確認」で照合できます。新しい保存依頼や接続テストを追加する必要はありません。

利用者が保存した実HTMLを外部通信・ページスクリプトを停止したChromeで読み込み、本文認識と照合を検証しています。このHTMLはPC内で使用し、リポジトリへアップロードしていません。

## v1.3.4の結果URL入力

15秒ごとの画面更新で、入力した結果URLが消える問題を修正しました。入力中は欄を作り直さず、状態更新後も入力値を保持します。

「開いている保存ページから選ぶ」で、同じ保存先の個別の保存結果タブ、または対象プロフィールの保存一覧タブから候補を表示します。候補を押すと結果URL欄に入力されます。続けて「この結果の本文を再確認」を押してください。候補の取得は開いているページの読み取りだけで、保存要求・ページ移動・GitHubへの送信は行いません。候補を選んだだけでは保存済みにせず、従来どおり対象アカウントと本文を照合します。

保存一覧のURLを直接入力した場合は、そのURLが検索ページであることを表示します。

## v1.3.3のGETフォーム対応

利用環境の診断で確認した保存フォーム `id="submiturl"`、URL入力欄 `name="url" id="url"`、同一サイトの `GET /submit/` に対応しました。検索フォーム `GET /search/` は保存対象にせず、フォームの送信方法を変更せずに通常の送信を行います。従来のPOSTフォームも引き続き利用できます。

更新後に拡張機能を再読み込みし、設定画面を開き直して新しい「接続テスト（1件）」を実行してください。過去の失敗履歴は残ります。新しいテストで本文確認が完了したら「自動保存を開始」を押します。GET送信・処理中URLへの遷移・重複送信防止をオフラインの実ブラウザで検証しています。実サイトでの保存完了は利用者の接続テストで確認が必要です。

## v1.3.2のフォーム診断

保存先のトップページを開き、設定画面で「保存フォームの診断」を展開して「保存フォームを診断」を押すと、フォームの送信方法・送信先・入力欄名を表示します。入力値・トークン・Cookie・HTML全文は取得しません。診断は保存要求やGitHubへの送信を行わず、結果は端末内だけに保存します。認識できないフォームの原因を確認するための機能です。

## v1.3.1の修正

archive.liのフォームIDに依存せず、同一サイトのPOST送信先 `/submit` と `/submit/` を確認します。URL入力欄が複数ある場合は送信しません。429・レート制限の画面はフォーム変更と区別します。

旧版で「保存フォームの構造を確認できません」となった場合は、更新・再読み込み後に「接続テスト（1件）」を再実行してください。新しいテストで正しいフォームを確認できた場合に限り、この構造エラーによる一時停止を解除します。アクセス制限・人間確認の停止は解除しません。本文確認後に「自動保存を開始」を押してください。

実サイトでのフォームと保存成功は、利用者の接続テストで確認が必要です。フォームの修正はオフラインのChrome DOMテストで検証しています。

## v1.2.0からの更新

v1.3.10のZIPを展開して既存フォルダへ上書きし、拡張機能を再読み込みします。設定画面でarchive.liを選び「接続先を保存」で追加のアクセスを許可し、「接続テスト（1件）」の本文確認が通ってから「自動保存を開始」を押してください。接続済みならPATの再入力は不要です。旧版のGhostarchive接続テストの合格をarchive.liへ流用しません。

送信済みのGhostarchiveジョブと保存済みの結果は保持します。まだ送信していないジョブは、保存先変更後の走査でarchive.liへ引き継ぎます。手動保存ヘルパーも初期選択をarchive.liにし、明示的に記憶した保存先の選択は保持します。

## インストール

1. ZIPを展開します。
2. Chromeは `chrome://extensions`、Edgeは `edge://extensions` を開きます。
3. 「デベロッパーモード」を有効にします。
4. 「パッケージ化されていない拡張機能を読み込む」で、このmanifest.jsonが入っているフォルダを選びます。
5. 拡張機能をツールバーに固定します。

## 使い方

1. 自分で `https://x.com/settings/muted/all` を開きます。
2. 拡張機能を押し、「この1画面を取り込む」を押します。
3. トラッカーの新しいタブが開き、画像認識が始まります。
4. 画像と候補を照合し、自分のXユーザー名を入力して登録します。
5. 続きがあればX側で自分でスクロールし、再度押します。

画像に写るユーザーだけが対象です。自動スクロール・巡回・ミュート・XのDOM取得・非公開API通信は行いません。画面外のアカウントをミュート解除扱いにしません。

## 1日1回の定期取得

1. 同じXアカウントのミュート一覧を開き、拡張機能に自分のXユーザー名を入力します。
2. 「専用ウィンドウへ移して定期実行を開始」を押します。そのタブを専用ウィンドウへ移し、初回は24時間後に1画面を取得します。既存タブに対してクリックで得たactiveTab権限を使い、全サイトへのアクセス権限は追加しません。
3. 専用ウィンドウのミュート一覧を選択したまま保持します。最小化せず、通常の作業には別ウィンドウを使ってください。画面のスクロール位置は自動で変更しません。同じXアカウントのまま利用してください。
4. 取得した画像の確認画面は別のウィンドウに開き、通知します。通知をクリックして候補を確認・登録します。登録そのものは自動実行しません。

スリープ中は撮影せず、復帰後に未実行分を最大1回だけ処理します。ブラウザを再起動したり拡張機能を更新した場合は権限の再登録が必要です。ミュート一覧で拡張機能を開き、開始ボタンを押し直してください。画像取得の権限がない・タブが閉じられた・別のタブが選択されている・ページ読み込み中・ウィンドウが最小化されている場合は撮影を中止し、通知と拡張機能のバッジに表示します。OS側で通知が無効な場合も、拡張機能を開くと状態を確認できます。

「定期実行を停止」でタイマーを停止します。専用ウィンドウは自動では閉じません。日々の結果と次回予定時刻は拡張機能の画面に表示します。

## 権限とデータ（詳細）

- activeTab: 拡張機能を自分で開いたタブのURL確認と、表示中の1画面の撮影に使います。
- storage: 自分のXユーザー名の端末内保存と、撮影画像の一時受け渡しに使います。
- alarms: 24時間ごとの定期取得を予約します。スリープ中にPCを起こす機能はありません。
- notifications: 取得完了、取得できない理由、再登録が必要なことを通知します。
- コンテンツスクリプト: `yamada1221.github.io/x-archives/` のトラッカーにだけ画像を渡します。Xのページにはスクリプトを挿入しません。
- 手動撮影はクリック1回につき1回です。定期取得を有効にした場合は24時間ごとに1回です。取得中にタブが変わった場合は破棄します。
- 画像は拡張機能のセッション内メモリーに一時保持し、受け渡し完了または受信タブを閉じたときに削除します。10分経過後は受け渡しを拒否して削除します。ブラウザ終了や拡張機能の再読み込みでも消えます。
- トラッカー内で画像を解析します。画像を外部OCRサービスへ送信しません。認識用データの初回ダウンロードにはインターネット接続が必要です。
- Xのパスワード、Cookie、APIトークンは取得・保存しません。Chromeウェブストアへの登録は行っていません。
